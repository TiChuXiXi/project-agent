# Save Progress Command

你正在执行"保存进度"操作。请严格按照以下流程完成本次会话的归档工作。

## 0. 纠错检视（LESSONS 前置过滤）

在执行任何归档之前，先回顾本轮会话：

- 我是否曾被用户纠正过？（包括"不对"、"应该是"、"换个方式"、"不要这样"等否定反馈）
- 若是，请**立即**按 `LESSONS.md` 的分类格式记录一条新教训，**然后再**继续执行后续步骤 1-5。
- 记录规则：
  - 读取根目录 `LESSONS.md`（不存在则创建，从 project-memory-setup skill 的模板复制）。
  - 选择最匹配的分类表格（如"Java/Spring 规范"），追加一行：`日期 | 错误做法 ❌ | 正确做法 ✅ | 原因/后果 | 关联文件/模块`（日期格式 YYYY-MM-DD）。
  - 写入前检查该分类是否已有完全相同的教训：若有则不重复写入，仅将原教训日期更新为最新。
  - 若无合适分类，新增分类并更新顶部的分类索引。
- 若否，直接进入步骤 1。

## 1. 提取本次会话摘要

回顾本轮对话，用 3-5 句话总结：

- 解决了什么问题/实现了什么功能？
- 涉及了哪些核心文件/模块？
- 是否引入了新的依赖或环境变更？

## 2. 更新任务跟踪 (Tasks)

- 读取 `.opencode/tasks/index.md`。
- 根据摘要，找到对应的任务条目（若不存在则新建）。
- 将当前进度写入该任务的 `progress.md`（如果该任务有专门的进度文件），或直接更新 `index.md` 中的状态（如：`[进行中]` -> `[待审查]` 或 `[已完成]`）。
- 记录本次涉及的具体文件变更清单。

## 3. 更新长期记忆 (Memory)

- 读取 `.opencode/memory.md`。
- 如果本次会话产生了新的架构决策、技术选型或踩坑经验，请更新 `memory.md` 中的"跨任务技术决策"章节（即"决策"表格，若表格不存在则新建该章节）。
- 注意区分：**用户纠正**写入 `LESSONS.md`（步骤 0 已处理），**主动决策/踩坑经验**写入 `memory.md`，两者不混写。

## 4. Git 提交（可选操作）

询问我是否需要提交当前变更。

- 如果需要，执行 `git add .`，并基于步骤 1 的摘要生成规范的 Commit Message（遵循 Conventional Commits，如 `feat:`, `fix:`, `refactor:`）。
- 如果不需要，跳过此步。

## 5. 完成汇报

向用户输出一份结构化的"保存报告"，包含：

- 更新的任务列表
- 新增/更新的记忆条目
- 新增的教训条目（如果有，注明写入 LESSONS.md 的分类和行数）
- Git 提交状态（已提交/已跳过/待确认）

执行完毕后，回复："✅ 进度已保存至 [当前时间]"
