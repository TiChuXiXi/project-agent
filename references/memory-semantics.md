# 长期记忆语义

项目 CONTEXT.md 与任务 context.md 各自记录背景（场景与使用者）、原因（具体痛点及影响）、目的（为谁实现什么价值的精简自然段）、最终目标（完成后可观察体验的精简自然段）。简单小修引用已有目标即可。当前版本、适用范围、确认项和来源随记录保存；缺失的动机写待确认。项目级约束由任务继承，任务局部变化不自动上升为项目约束。

重要记录全项目唯一：G-数字 为目标，D-数字 为决定，P-数字 为计划；已使用 ID 永不回收。工具将 ID 放在 Markdown 注释内，链接只做导航。正文用 ID 或 G-001@v1 指定依据，决定引用目标，计划引用目标/决定，实际变更、源码位置与验收引用相应计划或目标。归档保留标记，resolve 按 ID 查文件，缺失或重复须处理。

用户确认目的或最终目标时，将确认原话或用户确认过的精简版连同范围和出处作为不可变目标版本保存。只确认目的时明确写出最终目标仍待确认。每个版本独立区块，普通保存不能覆盖。用户明确调整目标后追加下一版：列旧约定、新约定、用户原话或可核验来源、受影响决定/计划/验收；读取时最新版本取代旧版，历史引用仍可查。Agent 建议的调整保存在探索区。来源无法复核、只剩无出处摘要时，不提升确认等级。

探索区按需记录真实痛点、备选方案、谁倾向什么、排除理由与未决问题。设计收敛时只提升被确认的具体部分。重要决定分别注明：
- 决策边界 LOCKED（用户锁定的目标和行为）、GUIDED（授权内可替换的方法）、OPEN（尚待解决的取舍）。
- 证据 user_confirmed（用户原话和确认对象）、source_verified（文件、符号、测试或观察）、agent_proposed（推断或建议）。同一决定可列不同证据支持的具体部分。
- 状态 candidate / active / superseded；替代决定用新 ID，保留旧文、替代理由和双向 ID。过期资料仅作历史。
- 实施授权单列于 progress.md，记录批准对象、计划版本、范围、来源及排除项。局部认可只作用于对应部分；源码和重复摘要无法证明用户授权。

重大设计、范围扩大、可见行为变化、长时间调试后换路线或最终验收时，重读原始场景。衡量复杂度能否换来用户需要的结果。仅受影响的决定需重新讨论。普通实现选择在已批准范围内处理。

恢复顺序：定位任务 → 项目与任务当前意图 → 有效决定（探索中则读倾向及开放问题）→ 实际批准范围 → 进度及验收缺口 → 核对当前源码。缺少授权证据时可以调查事实。记忆有冲突时展示具体差异。

验收按原始场景分别登记代码完成、技术验证、真实环境验证、用户体验确认。各项使用 待验证 / 通过 / 未通过 / 不适用（说明理由），附范围、环境及出处。客观目标可凭覆盖该目标的实证关闭；体验要求由对应体验证据关闭。技术通过可与体验待确认并存。

例：用户说“先试按需地图，效果差再评估官方工具”。保留其原话为方案顺序的来源。命中率阈值仍是 agent_proposed；批准编写轻量地图只覆盖该计划。真实测试能证明入口是否找对。若目标还包含新会话使用体验，交接给另一位 Agent 并取得相应反馈后再关闭。
